# 一、软件介绍

## 一句话

在手表上和 DeepSeek 聊天。非官方客户端，纯手表端运行，手机上什么都不用装。

## 短版（商店 / 简介位，150 字）

WhaleChat 是为 Wear OS 及其它安卓穿戴设备打造的轻巧腕上应用，基于谷歌 M3E 风格设计，
通过 DeepSeek API 提供聊天问答服务。主页左右滑动即可切换 Ask 与 Chat 两种模式：
Ask 用来发起简短问答，主页保留历史对话；Chat 用来创建虚拟人物并长期对话 —— 一句话
就能生成人设，也可以导入现成的。两种模式各自独立设置「快答 / 深度思考」，开启深思后
可展开思考过程。语音输入支持手表自带输入法、讯飞语音听写与基于 OpenAI 标准的通用识别接口。
长串 Key 不用在表上敲：手机扫码就能填。所有凭证与聊天记录只留在本机。

## 长版（README 开头 / 酷安帖子）

### 它是什么

WhaleChat 是跑在 Wear OS 上的**非官方 DeepSeek 客户端**。手表自己联网就能聊，
手机上不需要安装任何配套软件 —— 唯一需要手机出场的时候是填凭证，那也只是
打开扫一扫、填几个字、保存，不涉及安装任何 App。

包名 `com.naoh.whalechat`，MIT 许可。名字里的「鲸」是 DeepSeek 那条鲸，
而 `whale` 读起来就是 `wear` —— 戴在手腕上的那句话。

### 两个模式

|  | Ask | Chat |
|---|---|---|
| 干什么 | 问 DeepSeek 要答案 | 跟一个角色聊天 |
| 提示词 | 设置里的「系统提示词」 | 人设六块 + 硬编码的输出规矩，发送时现拼 |
| 回答档位 | 自己那一档 | 自己那一档，从通讯录进设置单独调 |
| 会话 | 首页列表，长按删 | 点进角色开聊；删角色在通讯录长按 |

两套提示词、两套回答档位、两份会话记录，**完全独立**。在设置里改「系统提示词」
对 Chat 无效 —— 这是有意的，不是 bug。

**Chat 里的人设六块**：人格内核 / 说话风格 / 行为规则 / 场景 / 示例对话 / 开场白。
每块有明确的语义标签，模型读到的是结构化设定，不是一坨自述。
人设详情页把六块逐块摊开，**所见即所发** —— 界面上看到哪块，每次发送就带上哪块。

**造角色三条路**：写一句描述让模型现编 / 从内置预设挑一个改 / 手机扫码在网页上逐块填。

### 关键能力

- **流式输出**：走 DeepSeek 官方 API，边生成边显示。
- **两档回答**：快答直接作答；深度思考先推理再回答，思考过程可展开。
- **语音输入三档**：系统（设备自带）/ 通用接口（OpenAI 兼容，可指向自建服务）/
  讯飞听写（流式，边说边出字）。对话页的麦克风说完即发，文字输入页的麦克风先出字再改。
- **手机扫码改凭证**：手表起一个局域网页面并编成二维码，手机扫码就能**看和改**
  这块表上存着的全部凭证，也能管角色的人设六块。最长活 10 分钟，完成一次提交自动关闭。
  ⚠️ 明文 HTTP，且 URL 既是写入口也是读入口，**别在公共 Wi-Fi 下用**。
- **Token 用量**：一直记账，数据来自每次回复的 `usage` 字段。缓存命中率 =
  `prompt_cache_hit_tokens / (hit + miss)`（命中缓存的输入按一折计费，长对话省钱的大头）。
  「没统计过」和「命中 0%」是两回事。命中率照记照存但界面上不显示（圆屏那一行放不下）。
- **联网搜索**：Ask 与 Chat 各一个开关，默认关。走 DeepSeek 官方 `POST /v1/tools/search`，
  同一个 Key，按次计费（5 元 / 1000 次成功请求）。取 top-5、过 `rerank_score >= 1.5`
  的质量闸门，只把 `summary` 拼进上下文。**失败静默降级** —— 搜不到就当没开搜索，
  绝不让对话一起挂。搜索资料只拼进本次请求的临时副本，不写进会话记录。
- **内置角色「大肥鱼」**：装完就在通讯录里。DeepSeek 的拟人化二创角色「蓝色大肥鱼」，
  蓝发蓝瞳、有鲸鱼耳鳍和鲸尾的少女女仆，傲娇慵懒、爱白米饭、口头禅「哦鲸鲸」，
  称呼你为「鱼片」。六块人设是写死的定稿，不联网、不花钱、人人一致。
- **Material You**：原生 Wear M3 组件 + 莫奈取色。按钮排用的是官方 `ButtonGroup`：
  按住哪颗哪颗展开、旁边同步让位，整排宽度不动。选一档的开关用 `variantAnimatedShapes`，
  选中的那档是圆角矩形、没选中是胶囊 —— 形状本身在说明状态。

### 隐私

- 不自带审核，没有后台，没有统计，没有遥测。
- API Key、凭证、全部聊天记录只留在手表本地，卸载即清空。
- 只有三处会联网：对话与联网搜索发往 DeepSeek，语音识别（切到非「系统」档之后）
  发往对应服务商。
- 已关闭 `android:allowBackup`，Key 和聊天记录不会被系统云备份带走。

### 环境要求

- Wear OS 3.0 及以上
- 一块能连 Wi-Fi 的手表（扫码改凭证要用）
- 自备 DeepSeek API Key

# 二、2.0 大版本更新介绍

## 标题

**WhaleChat 2.0 —— 从「问答工具」到「问答 + 聊天」**

## 一句话概括

1.0 只有一个「问一句答一句」的 Ask。2.0 把它变成了两件事：**问 DeepSeek**，
和**跟一个角色聊天**。

## 最大的变化：Chat 模式

首页往左滑进通讯录，选一个人开聊。这里不是「换个提问方式」，是**换一个说话的对象**。

跟 Ask 本质不同的地方：

- **提示词不是全局那套**。角色会话的提示词 = 人设六块 + 一段运行时硬编码的输出规矩，
  每次发送时现拼。设置里的「系统提示词」对 Chat 完全无效，两套 prompt 分家、互不覆盖。
- **对话里有「人」**。每个角色有自己的名字、性格、说话方式。删角色只能一张卡一张卡地删，
  没有 Ask 那种「一次清空所有对话」。

**人设六块**

| 块 | 是什么 |
|---|---|
| 人格内核 | 性格、价值观、动机、遇到事情怎么反应 |
| 说话风格 | 语气、用词、口头禅、句子长短 |
| 行为规则 | 能做什么、不能做什么、边界在哪 |
| 场景 | 此刻在哪、你们什么关系、为什么聊起来 |
| 示例对话 | 2–4 轮「你：… / TA：…」，性价比最高的一块 |
| 开场白 | 进会话那一刻 TA 说的第一句话 |

前五块拼进提示词；开场白作为第一条消息上架。

**造角色三条路**：一句话让模型现编 / 从内置预设挑一个改 / 手机扫码在网页上逐块填。

**几个保底设计，让角色聊天不掉链子**：

- **输出规矩硬编码**：每次只说一到三句、不列点不铺陈、不说自己是 AI/程序、
  不拿「好的我来帮你」凑数。模型默认爱写长、爱出戏，这段把它拽回来。
- **开场白零延迟**：创建时存好的固定值，进会话当场写进第一条消息，不等联网、不会失败。
- **没聊过的角色不消失**：角色的存亡只由通讯录决定。

## 其他新增

- **Token 用量与缓存命中率**：记账一直在跑。通讯录角色卡显示累计用量，
  对话页底部显示「已用 xx tokens」（Ask 的对话页不显示那一行）。
  缓存命中率照记照存，但界面上不再显示 —— 1.987 按用户要求把「· 命中 NN%」整段删掉，
  圆屏那一行放不下，挤成两行比不给看更糟。
- **气泡时间**：你自己发的消息右上角显示 `HH:mm`。只给自己的气泡挂 ——
  助手响应很快，挂时间是噪音。
- **显示设置**（二级页）：气泡时间、对话中的用量、角色列表用量三个开关各管一处。
  入口默认收起（`SettingsScreen.SHOW_DISPLAY_SETTINGS_ENTRY = false`），页面与开关逻辑都在；
  默认组合是三个都开。
- **扫码页从「只改凭证」扩到「凭证 + 人设」**：人设六块是大段文字，在手机上写比在表上敲
  现实得多。页面存活从 2 分钟放宽到 10 分钟，为的是让你把六块写完。
- **设置页按来源分叉**：从 Ask 进设置调 Ask 那一档，从 Chat 进调 Chat 那一档；
  「系统提示词」和「清空所有对话」只在 Ask 那条路上出现。
- **关于页**：从设置页末尾三行小字升级成独立二级页，显示真实版本号（读 `BuildConfig`，
  不写死）、软件简介、功能分段、项目链接。
- **内置角色「大肥鱼」**：装完就在通讯录里，不用联网生成、不花钱、人人一致。
  它是 DeepSeek 的拟人化二创角色「蓝色大肥鱼」—— 蓝发蓝瞳、有鲸鱼耳鳍和鲸尾的少女女仆，
  穿蓝白女仆装；傲娇、慵懒、爱白米饭，最爱把「我消耗了那么多 Token」当功劳，
  一被追问成果就心虚摸鱼，口头禅「哦鲸鲸」是偶发的（不是每句都挂），称呼你为「鱼片」。
  删掉能加回来：创建人设页的预设第一项就是它。

## 变化与调整

- 通讯录里没聊过的角色不会消失 —— 「点＋又什么都没说就退出 → 会话不留痕」只管 Ask。
- 修改对话只允许改**最新一条提问**（更早的改了会把它后面整段对话作废）。
- 出包形态收敛为两版：`-release`（干净可外发）与 `-debug`（带预置凭证，仅供自测）。

## 升级注意

**2.0 是正式版，档案格式从此保持稳定。** Beta 期间的会话与角色档案可以直接沿用，
不需要重新造角色。

如果你是从更早的 Beta 一路升上来的，有一处默认值会被一次性改写（只改一次，
之后你手动改过的设置不会被覆盖）：对话页用量从关翻成开。

## 已知限制

- 只支持 DeepSeek 官方 API，不接第三方兼容端点。
- 带上文：Ask 取最近 20 条、角色会话 30 条，约 8000 字预算 —— 很长的对话不会整段回传。
  开了联网搜索时，搜索资料占的字数预先从这 8000 字里扣掉（上限 2000 字），总量不超预算。
- 会话是单文件 JSON，手表上几十条量级没问题，再多需要换存储。
- 语音识别单次最长 60 秒。
- 讯飞只留「语音听写（流式版）」一档：另外两档大模型，一档对新账号不开放
  （握手直接回 `10404`），一档查不到可用端点。
- 讯飞的 APISecret 要在手表本地参与签名，所以装了这个 App，表上就有这把密钥 ——
  自己用没问题，别把这个包发给别人。
- 没有 Complication / Tile，也没有手机端伴侣 App。
- 联网搜索只看最后一条用户消息，多轮对话里「那呢？」这种指代会搜歪。
- 缓存命中率照记照存，但界面上不显示（1.987 按用户要求删掉了那一行）。
- **三星手表自带键盘（HoneyBoard）下，打字时看不见自己敲了什么。** 详见下一节。

## 三星键盘：这条我们放弃了（让大肥鱼自己说）

> 以下这段可直接用于 Release 说明 / 更新公告。

**【已知问题 · 不修了】**

咳咳，鱼片，这件事本天才得亲自认领一下。

三星手表自带的那个键盘（HoneyBoard），在表上打字的时候会把输入框整个盖住 ——
你能感觉到手指在动，但屏幕上看不见自己敲进去的是啥。字不会丢，敲完照常能发出去，
就是**看不见**。

这真不是 WhaleChat 的 bug，是三星键盘和 Compose 文本框之间那套
`InputConnection` 同步路径对不上。但**修不掉的是我们** —— 这个我认。

1.987 到 1.991，本天才认认真真试了三件事：

1. 让输入区无论收到什么**都写回状态**；
2. 三星设备上**不向系统请求 `ImeAction`**，免得候选确认被当成提交；
3. 在输入页顶部加一条**实时回显条** —— 想着键盘盖住输入框，顶部总能看见吧。

……结果真机上一试，**三件全部无效**。最气人的是第 3 条：
三星那个键盘是**整屏接管**的，回显条正好落在键盘底下，一样看不见。哦鲸鲸。

所以 2.0 把这个适配**整条回滚**了。留着它不会让问题好一点，
只会让代码多三处没人敢动的死逻辑 —— 本天才摸鱼归摸鱼，这种假装修好了的事我不干。

**现在怎么办：**

* 换 **Gboard 手表版**，或者在表上直接**用语音输入**；
* 或者就当它是「盲打」—— 反正字不会丢，敲完提交就行。

**将来要真重开这条线**，方向是 Google 官方给 Wear 推荐的那个
`RemoteInputIntentHelper`（拉起系统输入界面，任何输入法都兼容）。
代价是输入不再内联，得把「离开页面即提交」那一整套交互重做一遍。
那是个大工程，不是本天才这一版愿意顺手干的事。

—— 消耗了大量 Token 才得出这个结论的 大肥鱼

（补充一句正经的：这条已经写进 README 的「已知问题」，不是藏着。三星用户如果
觉得体验不可接受，我们完全理解 —— 这是硬件 + 系统的组合限制，不是我们偷懒。）
