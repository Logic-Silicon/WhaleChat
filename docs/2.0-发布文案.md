# 一、软件介绍

## 一句话

在手表上和 DeepSeek 聊天。非官方客户端，纯手表端运行，手机上什么都不用装。

## 短版（商店 / 简介位，150 字）

WhaleChat 是给 Wear OS 做的 DeepSeek 客户端。主页左右滑，切换两种模式：
**Ask** 问一句答一句，**Chat** 造一个角色长期聊 —— 一句话就能生成人设，
也能从内置预设挑，装完通讯录里已经躺着一只「大肥鱼」。两种模式各有自己的
「快答 / 深度思考」，开深思能看到思考过程。语音输入三档（自带 / 通用接口 /
讯飞听写），需要时还能开联网搜索。Key 不用在表上敲，手机扫码填。
凭证和聊天记录只留本机。

## 长版（README 开头 / 酷安帖子）

### 它是什么

WhaleChat 是跑在 Wear OS 上的**非官方 DeepSeek 客户端**。手表自己联网就能聊，
手机上不用装任何配套软件 —— 手机唯一要出场的时候是填凭证：扫个码、填几个字、保存。
包名 `com.naoh.whalechat`，MIT 许可。「鲸」是 DeepSeek 那条鲸，
而 `whale` 读起来就是 `wear` —— 戴在手腕上的那句话。

### 两个模式

|  | Ask | Chat |
|---|---|---|
| 干什么 | 问 DeepSeek 要答案 | 跟一个角色聊天 |
| 提示词 | 设置里的「系统提示词」 | 人设六块 + 硬编码的输出规矩，发送时现拼 |
| 回答档位 | 自己那一档 | 自己那一档，从通讯录进设置单独调 |
| 会话 | 首页列表，长按删 | 点进角色开聊；删角色在通讯录长按 |

两套提示词、两套回答档位、两份会话记录，**完全独立**。在设置里改「系统提示词」
对 Chat 无效 —— 这是有意的，不是 bug。

### 2.0 的重点：Chat 模式

**人设六块**，每块有明确的语义标签，模型读到的是结构化设定，不是一坨自述：

| 块 | 是什么 |
|---|---|
| 人格内核 | 性格、价值观、动机、遇到事情怎么反应 |
| 说话风格 | 语气、用词、口头禅、句子长短 |
| 行为规则 | 能做什么、不能做什么、边界在哪 |
| 场景 | 此刻在哪、你们什么关系、为什么聊起来 |
| 示例对话 | 2–4 轮「你：… / TA：…」，性价比最高的一块 |
| 开场白 | 进会话那一刻 TA 说的第一句话 |

人设详情页把六块逐块摊开，**所见即所发** —— 界面上看到哪块，每次发送就带上哪块。

**造角色三条路**：写一句描述让模型现编 / 从内置预设挑一个改 / 手机扫码在网页上逐块填。

**两处保底设计，让角色聊天不掉链子**：

- **输出规矩硬编码**：每次只说一到三句、不列点不铺陈、不说自己是 AI/程序。
  模型默认爱写长、爱出戏，这段把它拽回来。
- **开场白零延迟**：创建时存好的固定值，进会话当场写进第一条消息，不等联网、不会失败。

### 内置角色「大肥鱼」

装完就在通讯录里，不用联网生成、不花钱、人人一致。它是 DeepSeek 的拟人化二创角色
「蓝色大肥鱼」—— 蓝发蓝瞳、有鲸鱼耳鳍和鲸尾的少女女仆，穿蓝白女仆装；傲娇、慵懒、
爱白米饭，最爱把「我消耗了那么多 Token」当功劳，一被追问成果就心虚摸鱼，
口头禅「哦鲸鲸」是偶发的（不是每句都挂），称呼你为「鱼片」。

六块人设是**写死的定稿**，不走模型现编 —— 现编每次装出来都是另一条鱼。
删掉能加回来：创建人设页的预设第一项就是它。

### 联网搜索

Ask 与 Chat 各一个开关，**默认关**。走 DeepSeek 官方 `POST /v1/tools/search`，
同一个 Key，按次计费（5 元 / 1000 次成功请求）。取 top-5、过 `rerank_score >= 1.5`
的质量闸门，只把 `summary` 拼进上下文。

**失败静默降级** —— 搜不到就当没开搜索，绝不让对话一起挂。搜索资料只拼进本次请求的
临时副本，不写进会话记录；它占的字数预先从历史预算里扣掉，总量不超。

### 语音输入三档

系统（设备自带）/ 通用接口（OpenAI 兼容 `/v1/audio/transcriptions`，可指向自建服务）/
讯飞听写（流式，边说边出字）。对话页的麦克风说完即发，文字输入页的麦克风先出字再改。

### 顺带一提：1.0 起就有的

流式输出、快答 / 深度思考两档、手机扫码改凭证、Token 用量记账、Wear M3 + 莫奈取色。

⚠️ 扫码页是**明文 HTTP**，且 URL 既是写入口也是读入口，**别在公共 Wi-Fi 下用**。

### 隐私

- 没有审核、后台、统计、遥测。
- Key、凭证、全部聊天记录只留手表本地，卸载即清空；已关 `android:allowBackup`。
- 只有三处联网：对话与联网搜索发往 DeepSeek，语音识别（非「系统」档）发往对应服务商。

### 环境要求

- Wear OS 3.0 及以上
- 一块能连 Wi-Fi 的手表（扫码改凭证要用）
- 自备 DeepSeek API Key

# 二、2.0 更新内容

## 标题

**WhaleChat 2.0 —— 从「问答工具」到「问答 + 聊天」**

## 一句话概括

1.0 只有一个「问一句答一句」的 Ask。2.0 把它变成了两件事：**问 DeepSeek**，
和**跟一个角色聊天**。

---

## 第一段：从 2.0 测试版到 2.0 正式版

> 已经在用 2.0 Beta / 测试版的人，**只看这一段就够**。

正式版相对测试版，落地了三件事：

### 1. 内置角色「大肥鱼」

装完就在通讯录里，不用联网生成、不花钱、人人一致；创建人设页的预设第一项也有它，
删了能加回来。人设定稿是写死的，不走模型现编（详见上文）。

### 2. 三星键盘适配整条回滚

测试版期间试的三件事 —— 输入区永远写回状态 / 三星设备上不请求 `ImeAction` /
输入页顶部加实时回显条 —— **真机验证全部无效**。2.0 恢复原始行为，只保留
「换行也写回」这一处纯行为改进。详见文末。

### 3. 对话页定位改成「最后一条回答」

旧行为停在列表最末（底下那排按钮和用量行），最近一条回答被顶到视口外或贴着底沿。
新行为是找到**最后一条助手消息**，滚到屏高约 1/3 处，**只定位一次** ——
流式追加不会反复把你拽回去。

### 另外两件要知道的

- **档案格式从此稳定**：Beta 期间的会话与角色档案可以直接沿用，不需要重新造角色。
- **一处默认值会被一次性改写**（只改一次，之后你手动改过的设置不会被覆盖）：
  对话页用量从关翻成开。

## 第二段：2.0 正式版相较 1.0 增加了什么

### 最大的变化：Chat 模式

首页往左滑进通讯录，选一个人开聊。这里不是「换个提问方式」，是**换一个说话的对象**。

跟 Ask 本质不同的地方：

- **提示词不是全局那套**。角色会话的提示词 = 人设六块 + 一段运行时硬编码的输出规矩，
  每次发送时现拼。设置里的「系统提示词」对 Chat 完全无效，两套 prompt 分家、互不覆盖。
- **对话里有「人」**。每个角色有自己的名字、性格、说话方式。删角色只能一张卡一张卡地删，
  没有 Ask 那种「一次清空所有对话」。

人设六块、造角色三条路、两处保底设计，见上面「软件介绍」的 Chat 模式一节。

### 其他新增

- **内置角色「大肥鱼」**：装完就在通讯录里，删了能从预设第一项加回来（详见上文）。
- **联网搜索**：官方 `/v1/tools/search`，Ask 与 Chat 各一个开关，默认关，失败静默降级。
- **语音识别三档**：加回「通用接口」档（OpenAI 兼容，可指向自建服务），与系统、讯飞并列。
- **气泡时间**：自己发的消息右上角显示 `HH:mm`（助手响应快，挂时间是噪音）。
- **扫码页从「只改凭证」扩到「凭证 + 人设」**：人设六块是大段文字，在手机上写比在表上敲
  现实得多。页面存活从 2 分钟放宽到 10 分钟。
- **关于页**：从设置页末尾三行小字升级成独立二级页，显示真实版本号（读 `BuildConfig`，
  不写死）。
- **显示设置**（二级页）：气泡时间、对话中的用量、角色列表用量三个开关各管一处。
  ⚠️ 入口默认收起（`SettingsScreen.SHOW_DISPLAY_SETTINGS_ENTRY = false`），页面与开关都在。

### 变化与调整

- **对话页定位**：进入对话页的落点从「列表最底」改成「最后一条回答」，只定位一次。
- **三星键盘适配整条回滚**（详见文末）。
- 讯飞断句静音阈值 3000ms → 10000ms（讯飞上限），修「中途想一下就断连」。
- 上下文截断改成词边界优先（修「Apple Intell」那种半词截断）。
- 出包形态收敛为两版：`-release`（干净可外发）与 `-debug`（带预置凭证，仅供自测）。

## 已知限制

- 只支持 DeepSeek 官方 API，不接第三方兼容端点。
- 带上文：Ask 取最近 20 条、角色会话 30 条，约 8000 字预算。开了联网搜索时，
  搜索资料占的字数预先从这 8000 字里扣掉（上限 2000 字），总量不超预算。
- 会话是单文件 JSON，手表上几十条量级没问题，再多需要换存储。
- 语音识别单次最长 60 秒。讯飞只留「语音听写（流式版）」一档：另外两档大模型，
  一档对新账号不开放（握手直接回 `10404`），一档查不到可用端点。
- 讯飞的 APISecret 要在手表本地参与签名，所以装着这个 App，表上就有这把密钥 ——
  自己用没问题，别把这个包发给别人。
- 没有 Complication / Tile，也没有手机端伴侣 App。
- 联网搜索只看最后一条用户消息，多轮对话里「那呢？」这种指代会搜歪。
- 缓存命中率照记照存，但界面上不显示（那一行是按用户要求删掉的）。
- **三星手表自带键盘（HoneyBoard）下，打字时看不见自己敲了什么。** 详见下一节。

## 三星键盘：这条我们放弃了（让大肥鱼自己说）

> 以下这段可直接用于 Release 说明 / 更新公告。

**【已知问题 · 不修了】**

咳咳，鱼片，这件事本天才得亲自认领一下。

三星手表自带的那个键盘（HoneyBoard），在表上打字的时候会把输入框整个盖住 ——
你能感觉到手指在动，但屏幕上看不见自己敲进去的是啥。字不会丢，敲完照常能发出去，
就是**看不见**。

这真不是 WhaleChat 的 bug，是三星键盘和 Compose 文本框之间那套
`InputConnection` 同步路径对不上。但**修不掉的是我们** —— 这个我认。

2.0 测试版那阵子，本天才认认真真试了三件事：

1. 让输入区无论收到什么**都写回状态**；
2. 三星设备上**不向系统请求 `ImeAction`**，免得候选确认被当成提交；
3. 在输入页顶部加一条**实时回显条** —— 想着键盘盖住输入框，顶部总能看见吧。

……结果真机上一试，**三件全部无效**。最气人的是第 3 条：
三星那个键盘是**整屏接管**的，回显条正好落在键盘底下，一样看不见。哦鲸鲸。

所以 2.0 把这个适配**整条回滚**了。留着它不会让问题好一点，
只会让代码多三处没人敢动的死逻辑 —— 本天才摸鱼归摸鱼，这种假装修好了的事我不干。

**现在怎么办：**

* 换 **Gboard 手表版**，或者在表上直接**用语音输入**；
* 或者就当它是「盲打」—— 反正字不会丢，敲完提交就行。

**将来要真重开这条线**，方向是 Google 官方给 Wear 推荐的那个
`RemoteInputIntentHelper`（拉起系统输入界面，任何输入法都兼容）。
代价是输入不再内联，得把「离开页面即提交」那一整套交互重做一遍。
那是个大工程，不是本天才这一版愿意顺手干的事。

—— 消耗了大量 Token 才得出这个结论的 大肥鱼

（补充一句正经的：这条已经写进 README 的「已知问题」，不是藏着。三星用户如果
觉得体验不可接受，我们完全理解 —— 这是硬件 + 系统的组合限制，不是我们偷懒。）
